B · Notas RTL
Reglas RTL del banner
  • El componente usa padding-inline, inset-inline y gap — se invierte automáticamente con dir="rtl".
  • El chevron es un icono direccional: se espeja con transform: scaleX(-1) en RTL.
  • El ícono de enlace externo (Rally point) también se espeja.
  • Los valores numéricos (countdown, coordenadas, hora) llevan dir="ltr" explícito para no invertir el orden de los dígitos.
  • El texto árabe es más compacto que el español — no hay problema de expansión en este caso.

B · Lógica del estado silenciado
Estado: silenciado-sin-novedad
Condición Resultado
Usuario pulsó 🔕 silencedSet ← todas las claves de ataques activos. Banner slide-up.
Polling devuelve ataques (todos en silencedSet) Banner permanece oculto. Sin acción.
Polling devuelve un ataque con clave nueva Banner reaparece (slide-down). silencedSet descartado. → Vista 10
Polling devuelve items vacío silencedSet se limpia. Banner oculto por "sin ataques" (no por silencio).

Clave de ataque: "village_game_id:impact_at_iso"
Ejemplo: "342:2026-06-08T09:15:33Z"

B · Notas de reaparición
Cómo se detecta un ataque "nuevo no visto"
  • Cada ataque tiene clave "village_game_id:impact_at_iso".
  • Cuando el usuario silencia, el contexto guarda silencedSet = Set<string> con todas las claves actuales.
  • En cada ciclo de polling, el contexto hace: items.some(a => !silencedSet.has(key(a))).
  • Si el resultado es true → el banner reaparece con aria-live="assertive" y silencedSet se descarta.
  • La etiqueta NUEVO en la Vista 10 es solo del playground: en producción NO hay marca visual de "nuevo" por aldea — el banner completo reaparece y el usuario ve la lista actualizada.

Nota de implementación (PO-3 + silencio): el visibilitychange handler dispara un poll inmediato al reenfocar el tab. Si durante esos minutos llegó un ataque nuevo, el banner reaparece en el mismo instante en que el usuario vuelve a mirar la pantalla.
